# Неверные параметры виртуальной таблицы (InvalidVirtualTableParameters)

## Описание диагностики

Диагностика сообщает о вызове виртуальной таблицы регистра, список аргументов которого не укладывается в список её параметров. Платформа отклоняет такой запрос ошибкой «Неверные параметры».

Параметры виртуальной таблицы читаются строго по позиции. Поэтому проверяются два случая:

* аргументов больше, чем параметров у таблицы. Обычная причина — условие, разбитое запятой вместо `И`: лишняя запятая сдвигает все последующие аргументы;
* в параметр, принимающий значение (период, список видов субконто, число записей), передано условие — сравнение, `В`, `МЕЖДУ`, `ПОДОБНО`, `ЕСТЬ NULL`, логическое выражение. Так бывает, когда условие по счёту поставлено в позицию `Субконто`.

Списки параметров известны для таблиц регистров сведений (`СрезПервых`, `СрезПоследних`), накопления (`Остатки`, `Обороты`, `ОстаткиИОбороты`) и бухгалтерии (`Остатки`, `Обороты`, `ОборотыДтКт`, `ОстаткиИОбороты`, `ДвиженияССубконто`). Вид регистра виден из текста запроса, поэтому проверке не нужны метаданные.

## Примеры

Условие на субконто разбито запятой — аргументов пять, а у таблицы `Остатки` регистра бухгалтерии четыре параметра:
```sdbl
ВЫБРАТЬ
	Остатки.Ресурс1Остаток КАК Ресурс1Остаток
ИЗ
	РегистрБухгалтерии.Бухгалтерия1.Остатки(&Период, Счет = &Счет, , Субконто1 = &Значение1, Субконто2 = &Значение2) КАК Остатки
```

Исправление — соединить условия через `И` в одном параметре `Условие`:
```sdbl
ВЫБРАТЬ
	Остатки.Ресурс1Остаток КАК Ресурс1Остаток
ИЗ
	РегистрБухгалтерии.Бухгалтерия1.Остатки(&Период, Счет = &Счет, , Субконто1 = &Значение1 И Субконто2 = &Значение2) КАК Остатки
```

Условие по счёту стоит в позиции параметра `Субконто`:
```sdbl
ВЫБРАТЬ
	Остатки.Ресурс1Остаток КАК Ресурс1Остаток
ИЗ
	РегистрБухгалтерии.Бухгалтерия1.Остатки(&Период, , Счет = &Счет, ) КАК Остатки
```
